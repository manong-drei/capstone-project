# Patient profile mockup prompts

Tool: built-in image-generation tool. No CLI/API fallback used.

Desktop was generated from the project visual brief. Laptop and the initial mobile draft used the desktop mockup as a style reference. The final mobile refinement used the initial mobile draft as a style reference. Only the final desktop, laptop, and refined mobile mockups are included in the deliverables.

## Shared brief

Use case: ui-mockup.
Create a high-fidelity production-quality UI DESIGN IMAGE, a flat screenshot of a proposed E-KALUSUGAN patient detail page. This is a healthcare queue and dental consultation application for Bago City in the Philippines. This is design exploration only. Visually consistent with the existing doctor and staff dashboards: full-width royal-blue top navigation, Poppins typography, restrained rounded white cards, light cool-gray canvas, thin slate borders, generous but efficient spacing, clear dark navy text, Lucide-style line icons. Fixed LIGHT theme. Color tokens: navigation gradient #1A3A8F to #1E4DB7; primary blue #1E4DB7; white #FFFFFF; canvas #F1F5F9; orange accent #F97316; soft orange #FFF7ED; navy #172B4D; secondary text #64748B; border #E2E8F0. Blue for primary actions and active navigation, orange for the current queue badge and useful emphasis. Avoid purple. Small textual status badges may use blue/gray. Avoid gratuitous dashboard charts, fabricated vitals, medical risk scores, allergies, billing, or medication data.
All patient details are FICTIONAL SAMPLE DATA. Same patient on every screen: Maria Clara Santos, initials MS, patient ID PT-001284, female, born March 18, 1992, age 34, registered patient. Mobile 0917 555 0128. Barangay Poblacion, Bago City. Emergency contact Juan Santos, phone 0918 555 0142. PhilHealth number shown masked as ending 4821. Account status Active. Today's current dental visit: queue D-018, Waiting, Regular, November 4, 2026, booked appointment, services Dental check-up and Oral prophylaxis. Last completed visit October 12, 2026. Visit history has 8 total visits. Do not invent a scheduled next appointment.
Product structure: back link to the originating dashboard, page title Patient profile, prominent identity summary, internal section tabs Overview (selected), Visit history (8), Consultations; staff/admin additionally get Account. Personal information, Emergency contact, Today's visit, and Recent visits are the substantive sections. These are sections of ONE patient's profile, not population stats. Do not place a role switcher in the product. A single shared profile layout serves all three roles; each screenshot shows a signed-in role with appropriate controls.
Polish: neat alignment, 16px card corners, very subtle shadows, readable body text and strong hierarchy, no large decorative hero photograph, no excessive gradients beyond the navigation. No laptop/phone hardware, no perspective, no staged desk, no browser address bar, no annotation arrows, no watermark. Edge-to-edge app screenshot with crisp English text and complete boundaries.
